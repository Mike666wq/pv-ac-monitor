## 自检

```
ExperimentMonitorDemo.exe --test-all --root=<可写目录>
```

报告把三种状态分开记：

| 状态 | 含义 |
|---|---|
| `passed` | 通过 |
| `failed` | 跑了但没过（附异常类型与消息） |
| `gaps` | **根本没写自动化用例**，附原因（需真机/现场）。不是 skipped，也不是 failed |

> **控制写入出厂全部关闭。** 4 个控制点都是 `confirmed:false / allowWrite:false`，
> 这是有意的（旧版本这两道闸门从未生效，曾向真实 PLC 写过 10 次）。

PV AC Monitor 是独立运行的 Windows 桌面程序，用于读取项目绑定的 Modbus RTU 测点、查看实时状态并记录本地实验数据。程序可与 BMS 并行运行，不修改 BMS 文件。**默认不发送任何 Modbus 写入命令**；0.7.0 起新增受控的 06 单寄存器写入，默认禁用，必须现场确认后手动解锁。

当前配置包含 4 台设备、37 个绑定测点。实时监控按温度、实验电表、市电、太阳能、控制/设定和运行状态分组，支持设备详情与实时/历史趋势。

> 当前版本：**0.9.2**。0.8.0 的主线是「让程序停止说谎」：每轮每点必有行（离线点显示"未读取"而不是静默消失）、控制门禁真正生效、导出不再用今天的点表改写历史、区分"命令值"与"实测值"。完整变更见 `CHANGELOG.md` 的 0.8.0 条目。
>
> **控制写入出厂全部关闭。** 随包 `control-config.json` 为 `mode=live`，但 4 个目标全部 `confirmed=false / allowWrite=false`，这两个字段自 0.8.0 起**各自独立生效**（不再受已废弃的 `requireConfirmed` 影响），因此不会发出任何 06 报文。要让某个点可写，必须显式把该点两个字段改成 `true`——步骤与风险见 `docs/field/CONTROL-ENABLE.md`。
>
> **0.7.x 的教训**：那两行门禁代码当初挂在 `requireConfirmed` 条件里，而它默认 `false`，于是整段被跳过。审计日志里有 **10 笔写进真实 PLC 的记录**发生在"配置声明不可写"的情况下。另外，写入**没有**逐次二次确认弹窗（`ControlConfirmForm` 从未被实例化），0.8.0 起也不再计划加——现场写入是成组爆发的调试行为，每次弹窗必然被肌肉记忆优化掉。

记录页与趋势分析页的左栏现在共用同一个「测点选择器」：设备是父节点、测点是子节点，设备节点显示已选/总数（例如 DS666（9/9））；勾选即决定**哪些测点参与取数**（查询、统计、导出都按它来），搜索框可按测点名/名称/设备名过滤，「全选 / 清空」作用于当前可见项，因此「搜 DS666 → 清空」就是按设备批量取消勾选。记录页的「列选择 ▾」只列取数范围内的测点，且只影响显示、不影响取数，改完立即生效且不重新查询。勾选变化后 400 ms 去抖自动重新查询，不必再点「查询记录」；摘要行的「筛选共 N 轮」在后台统计（范围大时约 3.5 秒），统计期间再改条件会排队重算，不会把上一次范围的旧数字留在界面上。
本版把记录页和趋势页的重复入口去掉了：记录页不再内嵌趋势图，改用 `在趋势页查看 ▸` / `看原始记录 ▸` 两条带条件的跳转（带上来源、时间范围、测点，跳过去自动退出跟随）。记录页新增两个统计子标签——「实验段」按采集会话（一次「开始采集」算一段）汇总起止/时长/轮数/应有轮数/缺口/最大间隔/超时轮/越限轮，双击一行可定位到该段；「测点统计」按测点给出有效点/超时点/越限点与最小/最大/均值/标准差/平均采样间隔，其中下限、上限可直接在表里编辑并保存。阈值表保存在运行目录的 `limits.json`，越限值在记录页标红，趋势图在单测点分栏里画上下限虚线；导出 xlsx 会多出一张「统计摘要」工作表（未先统计时写明未统计）。趋势页还能把当前可见区间「导出图片 ▸」成 PNG。通信诊断页「最近一次读取」旁有「历史会话日志…」，打开独立只读窗口即可浏览 `logs\session-*.log` 的样本数/超时数并预览最后 200 行。
数据记录页的职责是「精确定位到某一刻、看原始值、导出」，「看全天」由趋势分析页负责（按范围分桶压缩绘制）。记录页表格正上方是一条固定的分页导航条：« 最早 / ‹ 更早 / 本页 N 轮 / 更新 › / 最新 »，下面一行显示本页覆盖的时间段、是否还有更早或更新的数据，以及每页 200/500 轮、跳到开始时间、跳到该时刻 两条锚点跳。导航按时间锚点重新定位，不提供页码输入框；「跳到该时刻」返回包含该时刻的完整采集轮，锚点落在无数据空档期时落到其后的最近一轮。

## 使用 Release 版本

运行要求：Windows 和 .NET Framework 4.8。

1. 从 [GitHub Releases](https://github.com/Mike666wq/pv-ac-monitor/releases) 下载 Windows 应用 ZIP。
2. 将 ZIP 中的完整目录解压到当前用户有写入权限的位置。
3. 启动 `ExperimentMonitorDemo.exe`。

程序启动时模拟设备默认关闭（忽略旧设置中保存的模拟勾选，需每次手动开启），云端上传默认关闭，不会自动打开串口或自动采集。硬件运行时，先停止其他程序对同一串口的轮询，再刷新并选择串口。

趋势分析：勾选“跟随最新记录”显示滚动窗口（默认最近1小时）；数据截止时间在状态栏显示，无新记录时范围保持不变。手动修改开始/结束时间会暂停跟随，点击“应用范围”后查询固定范围（结束时间不含），不停止后台采集。“回到最新”按当前范围时长恢复跟随。最近15分钟/1小时/2小时为滚动窗口，“今天（固定）”为固定范围。来源和测点可独立筛选；普通滚轮滚动页面，Ctrl+滚轮缩放或拖动会暂停跟随，双击恢复已应用范围。

连接只打开通信通道，不会自动采集。选择“开始采集”后程序才轮询并记录；“停止”会等待本地写入排空并保持连接；“断开”释放串口。通信诊断中的手动读取要求周期采集已停止，诊断报文不计入正式样本。设备通信使用 Modbus RTU 功能码 03，只读寄存器。

在 Windows 上安装 .NET Framework 4.8 和相应开发工具后，在源码目录运行 PowerShell：

```powershell
.\build-source.ps1
```

可选运行完整内置自测：

```powershell
.\build-source.ps1 -Test
```

程序及运行依赖输出到 `bin\`。`-Test` 会将程序、配置和 SQLite 依赖复制到 `bin\self-test-<随机编号>\`，从该隔离目录运行 `--self-test`。测试使用模拟传输及本机 HTTP mock，不打开实体串口、不访问生产云；测试数据库、设置、日志、截图和结果 JSON 都留在隔离目录，不接触源码目录旁的现场数据。

**所有产物都留在本目录**（不创建外部工作区）：

| 用途 | 路径 | 命令 |
|---|---|---|
| 构建输出（可直接运行） | `bin\` | `.\build-source.ps1` |
| 本地程序（日常运行的就是它） | 仓库根目录 `ExperimentMonitorDemo.exe` | `.\build-source.ps1` 构建后**自动覆盖**，旧版本留成 `ExperimentMonitorDemo.exe.<旧版本>.bak` |
| 控制链路套件自测（control/storage/workflow/smoke/demo） | `test-output\` | `powershell -Command "& .\tools\control-runner\run-tests.ps1 -Suites control,storage,workflow,smoke"` |

构建脚本直接使用目录中的 C# 源文件、协议配置和 SQLite 二进制；不依赖本地验收、数据保护或基线脚本。

仓库提供 `.github/workflows/windows-release.yml`。推送 `main` 或 Pull Request 时由 GitHub `windows-latest` 构建并运行完整隔离自测，然后将完整运行目录压成 ZIP 作为短期 Actions Artifact；推送与 EXE 版本一致的 `vX.Y.Z` 标签时，同一 ZIP 会自动上传到 GitHub Release。因此日常开发无需在本机长期保存历史构建包。`package-ci.ps1` 的暂存目录与 ZIP 输出均可放在 CI 临时目录，不写入现场数据目录。

## 本地数据和历史筛选

数据保存在程序运行目录下：主记录位于 `data\storage\`，采集日志位于 `logs\`；运行偏好和云配置位于 `settings.json`、`cloud-settings.json` 等配置文件，采集分期状态还保存在 `settings\` 与 `partition-days.json`。Release 运行时，这些路径相对于解压后的应用目录；源码构建运行时，相对于 `bin\`。

模拟来源与实机来源分开保存。每个来源可按时间分成多个 SQLite 分区，默认 30 天；可在数据记录页调整分期。历史筛选会查询所选来源的相关分区数据库，可跨多个时间分区筛选时间、设备和测点，同时保持模拟/实机隔离。程序只识别自身管理的记录布局及兼容的旧版布局，不是任意 SQLite 文件导入工具。

需要迁移或备份时，先关闭程序，再完整保留运行目录中的 `data\`、`settings\`、`settings.json`、`partition-days.json` 和 `cloud-settings.json`。不要覆盖运行中的目录。云令牌由当前 Windows 用户的 DPAPI 保护，复制到其他用户或设备后可能需要重新填写。

数据记录页提供宽表与逐测点明细，可按当前筛选范围导出 Excel 或 CSV。导出不会只限于当前分页，也不会把空值当成零；现有文件不会被覆盖。导出宽表与明细按当前点表显示名称（D1/D2 空调外机电压/电流、DU1/DU2 市电电压/电流、ZU6682/ZI6682 太阳能直流电压/电流等，旧历史记录同样按新名映射），宽表列名不带设备编号前缀；导出不包含 DS666 原寄存器(0006H) 与运行状态分组点（二者仍在界面显示并保存在数据库中），并省略轮次开始时间 UTC、来源、会话、采集轮列；采样时间 UTC、站号、地址、寄存器数、原始数值与原始 HEX 等列保留。

## 云端连接

本地云连接使用 HTTPS 和设备 Bearer 令牌，通过以下接口申请观看租约并上传最新实验快照：

- `POST /api/experiment/heartbeat`
- `POST /api/experiment/snapshots`
- `POST /api/experiment/backfill`

服务器授予有效观看租约并请求相应设备后，客户端才发送这些设备的最新快照；若心跳同时返回 `backfillSeconds=300`，新版云端还会按当前网页主趋势通过可选 `requestedHistoryPoints` 指定需要预热的 `设备/测点`，客户端只从本地 SQLite 查询这些测点最近 5 分钟的真实观测。若该字段缺失（例如滚动升级期间连接旧云端或旧网页），客户端保持兼容，回退为读取当前请求仪器的最近 5 分钟历史。历史预热运行在独立、可取消的低优先级后台任务中，主心跳和最新实时快照不会等待 SQLite 历史查询或 backfill 上传；主趋势、订阅或云配置变化会取消旧预热并按新订阅重新执行。回填保留原始观测时间、质量、会话与失败/null 语义，不替代当前快照，也不会上传完整历史。本地完整历史仍保存在 SQLite 中。模拟数据默认不上传。网络故障或认证失败不会中断本地采集；模拟与实机来源分别标记，失败或未响应测点不会转换成零值。

云端服务端由项目所有者另行推进。本机 mock 验证不覆盖生产端的 HTTPS 证书、账号权限、租约行为和页面联调，这些需要连接部署后的服务进行确认。

## 运行控制（默认关闭）

控制页只支持 16 位单寄存器（功能码 06），不做 PID、不做软 PLC、不做自动控制/定时，也不接受云端下行。

**操作方式（模拟和真实场景完全一样）**

1. 顶部工具栏：模拟测试勾「模拟数据」再「连接 → 开始采集」；真实测试选串口「连接 → 开始采集」。
2. 「运行控制」页：点 **控制开关**（默认「关闭」，打开后才允许发送）。
3. 在 **设定表** 里勾选要发送的控制点、填写「要发送的值」（**可以一次勾多个点一起发**），点 **发送勾选点**。
4. 页面立刻给出三样东西：**流程示意图**、**测试过程逐行日志**、**返回信号对比表**。

**流程示意图（与力控控制流程一一对应）**

```
① 操作员输入   →  ② 写变量 PV   →  ③ 驱动下置 06  →  ④ PLC 执行/回显  →  ⑤ 03 回读 PV  →  ⑥ 画面/审计
   D2202 = 26        PV.D2202 ← 26    02 06 08 9A 00 1A 2A 7D   回显一致，PLC 已接受      D2202 = 26      已写入审计表 + JSONL
```

这正是力控的上层做法：画面输入/按钮 → 写变量（力控用脚本，我们用显式事务）→ 驱动下置 06 → PLC 执行；力控同时一直用 03 采集 PV 回读，画面刷新、报警触发、历史留痕。力控想再复杂一点才买 FStrategy 软 PLC（这个工程里没有，也不做）。

**测试过程日志**逐行打印：输入值 → TX 报文 → RX 回显 → 03 回读值 → 返回信号变化 → 审计落盘位置，一目了然。

**返回信号**：页面下半部按 `feedbackPoints`（默认 D2208/D2209/D2210/D2211/D2212/D2213）显示「写入前 / 当前 / 变化」。设定值回读一致只说明 PLC 收下了命令；风机/主机/水泵/冷量/故障是否真的动作，看这一栏。模拟数据不伪造这些变化，所以模拟里通常显示「未变化」。

**默认关闭怎么保证**：`control-config.json` 的 `mode=disabled` 是强制关闭（任何操作都发不出去）；`mode=preview` 时由界面开关决定，程序启动时开关是「关闭」，要手动打开才能发送。`enforceInterlocks` / `requireConfirmed` 默认 false，联锁（D2003 远程、D2208 无故障）与现场确认状态只做提示不拦截，需要严格时把它们改成 true。

**调试细节（现场联调用）**：控制台顶部显示数据源与波特率、采集周期/超时、联锁点数值与数据年龄、本次会话发送统计；设定表带「采样时间」「上次写入」两列；右下「调试详情」保留最近一次写入的 **06 请求/回显、03 预读/回读原始报文**、旧值来源、回读耗时、操作者、配置版本与审计位置，可一键复制；「测试过程」可导出为文本留证。

**保留的硬约束**：一次只允许一个写入（下发本身串行，多点按顺序逐点发送并逐点回读）；1 秒冷却、每分钟最多 6 次；写后必须回显 + 03 回读（回显与请求不一致一律判「结果未知」）；结果未知**不自动重试**，需点「重新读取核对」；每次发送都写 `control_events` 表和 `logs/control-events.jsonl`（含操作者、TX、RX、回读值、配置版本）。控制点当前读数全为 0，真实场景建议先做同值写自检，详见 `CONTROL-DESIGN.md` 第 10 节。

**与力控的差异（研究结论）**：这份力控工程**本身没有任何控制配置**（动作库全为 0 条、无脚本、无 FStrategy，40 个点全建成模拟量点），所以本程序是**新建受控下置链路**而不是迁移既有配置；驱动层力控勾选的是 **06 写单寄存器**（未勾 16），与本程序一致。力控的官方链路是「画面动画连接 → 动作脚本 → View 变量 → DB 点 → I/O 驱动下置 → PLC」，**没有写后回读校验**（靠下一轮采集刷新人工判断）；本程序多做了一步「写完立即 03 回读 + 状态机」，这点比力控更严。力控有而本程序没有的是：脚本引擎/条件动作/数据改变动作、FC16 写多寄存器、用户权限与安全区、变量级安全级别、电子签名、点报警、FStrategy 软 PLC。

**现场两个坑**：① `D2001` 的**点名与地址不符**（连接项是 `HRS2202`，零基地址 **2201**，疑为原工程笔误 D2201），现场按名字核对会找错寄存器，以 `protocol.json` 的 `address_zero_based` 为准；② `0x00010000` 类型标志**不是读写权限**（太阳能纯读点也带这个高位），每个点是否可写仍然**无证据**，必须现场裁决。

## 协议资料与核对（2026-11-06）

本项目底层通信协议已由用户补充的六份物料核对完成，结论与逐条证据见：

- `docs/protocol/fx3u.md` —— 三菱三份手册（MODBUS 从站映射、D8400/D8414、32 位字序、保持区）
- `docs/protocol/meters.md` —— DDSU666 表 8 + 直流表地址表（含红字批注与分流器）
- `docs/protocol/forcecontrol.md` —— 新版力控工程包重解析
- `docs/protocol/implementation-audit.md` —— 现有代码/文档的一致性审计

需要记住的四条：

1. PLC 是三菱 FX3U 兼容机（`EX3U-80`）+ MODBUS 从站，`D n` 就是保持寄存器**地址 n**；站号 2，9600 8N1。
2. **float32 线上是 ABCD**（2026-10-03 抓包 `41 C9 99 9C` = 25.2 ℃）；FX2N 手册的"高位=大号码"规则与本机相反，**不要改成 CDAB**。
3. 电表：D6/DU6 = 功率因数（0x200A），D9 = 保留地址（0x200C）；功率单位是 **kW/kvar/kVA**；
   直流表电压 ×0.1 V、电流 ×0.001 A（0x0003，不是 0x0001），电流/功率还要再乘**分流器倍数**。
4. 四个控制点（D2000/D2001/D2202/D2207）都在 EEPROM 保持区，且可能落在文件寄存器区——只能人工单次写。

## 限制

程序**默认**不会控制设备；只有把 `control-config.json` 的 `mode` 改为 `preview`、在现场逐点确认并显式设置 `confirmed/allowWrite` 后才可能发送 06。具体硬件的测点倍率、PLC 状态含义和控制寄存器语义必须在现场确认；2026-10-03 实测 D2000/D2001/D2003/D2202/D2207/D2208～D2213 全部为 0，不能据此推断设备处于何种状态。UI 自动检查中的 125%/150% 是控件缩放模拟，不等于真实 Windows 显示器 DPI 验收。

记录页 960 像素宽的窄窗口下，分页条第二行的“覆盖时间段”文字会被省略（AutoEllipsis），定位与翻页控件不受影响。本机 1440×900 的 UI 自动检查另有一项“D3 数值绘制边界未裁切”失败，经与 0.4.6 同一构建流程对照，属既有的本机环境问题，与记录页改动无关。
