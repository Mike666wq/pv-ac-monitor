## 2. 由此确认的三个"字段错位"

### 2.1 功率因数：画面绑到 D9（0x200C 保留），真正的 PF 是 D6（0x200A）

- 手册（DDSU666 表 8，p.11）：`200AH = PF`、`200CH = RESERVED`。
- 力控主画面："总功功率因数" → **D9.PV**；而 D6 的 DESC 是"8202瞬时总功"。
- 结果：
  - 画面上"功率因数"一行读的是 0x200C（站号 6，且该表从未通信）→ **永远 0.00**；
  - 画面上"瞬时总功"一行读的是 0x200A → 实际显示的是 **PF 0.847**（历史库 600 点 0.74–0.80 可证）。
- App 现在把 D6 标"功率因数"、D9 标"保留(0x200C)"——**语义是对的**，但与力控画面相反；
  现场如果按力控画面找"功率因数"会找到 D9。

### 2.2 T1：主画面叫"水箱"，曲线画面叫"相变温度"，DESC 叫"相变温度2"

三者指向同一个 tag（HRS303→D302，16 位整数）。物理上到底是水箱温度还是相变2，
只有 PLC 程序/现场能定；在此之前 App 用哪个名字都是猜测。**建议显示为"水箱/相变2（待确认）"。**

### 2.3 D2206：主画面叫"相变"，DESC 叫"温度4"

地址 D127–128，浮点。它不在温度曲线里，也不对应"温度4"以外的已知传感器；
可能与 T1 是同一个物理量（相变2）的浮点副本，也可能是独立第 4 路温度。**待 PLC 程序。**

## 3. 类型：哪些点根本没有产出数值

力控绑定记录的类型码与 App 的解码方式：

| 力控类型码 | 条数 | 绑定 | 含义 | App 现状 | 判定 |
|---|---:|---|---|---|---|
| `0x00000007` | 21 | HRF | float32（2 寄存器） | `FLOAT ABCD` | ✓ 产出数值 |
| `0x00000002` | 1 | T1 的 HRS303 | 16 位整型 | `INT16` | ✓ 产出数值 |
| `0x00010002` | 14 | 11 个 PLC 状态/控制 + 3 个直流点 | 16 位整型 + 未知高位 | **`U16 / I16` / `UINT16`** | **✗ 见下** |
| `0x00010000` | 1 | 0006H 的 HRBS/L1 | 位/位串 | `RAW` | △ 只显示"原寄存器 701" |

**问题 1（最严重）**：`U16 / I16` 在 `Modbus.Decode` 里走的是兜底分支——只返回
`"U16=.. / I16=..（符号/倍率待定）"` 文本，**不设置 `Number`**。
后果：D2000/D2001/D2202/D2207/D2208/D2209/D2210/D2211/D2212/D2213/D2003 共 **11 个点**
在趋势图、历史统计、Excel 数值列里全部是空值，界面显示的是那串文本，而不是数字。

**问题 2**：三个直流点用 `UINT16`（无符号），而直流表手册写的是 `Int`（有符号）。
光伏电流反向/夜间倒灌时，负数会显示成 65xxx。

**问题 3**：`0006H` 是位/位串类型（HRBS/L1），App 按整寄存器读，显示 701（0x02BD）。
它不是一个物理量；如果保留，应明确标成"诊断位串"，且不应进入导出/统计。

## 4. 处理建议（按确定性排序）

| 优先级 | 动作 | 依据 |
|---|---|---|
| P0 | 11 个 16 位点改为 `INT16`（FX3U/EX3U-80 的 D 寄存器是"最高位为符号"的 16 位有符号数） | EX3U-80 第 14 页；力控类型码低 16 位=2 |
| P0 | 3 个直流点由 `UINT16` 改为 `INT16` | 直流表截图"数据格式 Int" |
| P1 | `0006H` 保留但标注"诊断位串"，不参与统计/导出（或直接移除） | 类型码 0x10000 位串 |
| P1 | T1/D2206 的显示名先采用"待确认"写法（水箱/相变2、相变/温度4） | 三处命名冲突，无 PLC 程序 |
| P2 | 若现场确认 T1 与 D2206 是同一物理量的整数/浮点副本，保留浮点、把整数点标为"备用" | 地址推断（D302 与 D127 都指向 AD1 相变2） |

## 7. 现场判读协议（2 分钟，只读）

App「诊断」页的 **只读 03 手动读取** 已把"寄存器数"上限从 8 放宽到 125，可以直接块读：

3. 在设备面板上逐个操作：风机 1/2/3/0、水泵开/关、主机开/关、改温度设定；
4. 每次操作后重读同一块，比较 14 个数的变化；

## 8. 判定：D2212 的 25→50 台阶是压缩机频率/负载，不是"冷量反馈"

2026-11-06 16:25 前后的实采（本地时间，`session-20261106-160648…log`）：

| 时刻 | 观测 |
|---|---|
| 16:25:18 | D2 电流 0.34 A → **9.72 A**；D3 有功 0.042 → **1.18 kW**（压缩机启动） |
| 16:25:37 | D2212：0 → **5** |
| 16:26:19 / 16:26:59 / 16:27:49 | 10 / 15 / 20（约每 40 秒 +5） |
| 16:28:39 → 16:36:09 | 25 / 30 / 35 / 40 / 45 / **50** |
| 同期 | T4 送水 21.9 → 9.4 ℃；T5 回水 13.7 → 11.0 ℃；D2 稳定在 4.5 A |

判定依据：
- 它不是温度（温度是连续变化，它是严格 +5 台阶）；
- 它不是电流/功率（D2 稳定 4.5 A、D3 稳定 0.94 kW 时它继续 +5）；
- 它只在压缩机运行期间从 0 开始爬升。
⇒ **D2212 = PLC 自己的斜坡量（最可能是变频压缩机频率 5–50 Hz，或负载率/档位），
"冷量反馈" 这个名字是力控作者贴的，与信号形态不符。**

**用户确认**：D2209 的 1→2→3→0 是现场在设备面板上切风机档位 → `D2209 = 风机档位` 成立，
App 标签已由"风机状态"改为"风机档位"。

**顺带发现**：
- D2211（力控叫"制冷主机"）在压缩机未启动时已经是 1 → 更像"主机就绪/允许"；
- D2213（力控叫"水泵"）在 16:20:49 / 16:22:29 有 1→0→1 的跳变，符合水泵启停。

**还需要现场确认一项**：设备面板上压缩机运行时有没有"频率/负载"显示（如 25→50 Hz）？
有的话就能直接给 D2212 定名；没有的话按"压缩机频率（待确认）"处理。
