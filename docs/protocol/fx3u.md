## 0. 一页结论（TL;DR）

1. **D n ↔ MODBUS 保持寄存器地址 n 的直映射成立**，有两条独立证据：三菱 FX3U 官方分配表
   （`FX3U编程通讯手册` 印刷 p.97）和 Coolmay 一体机分配表（`FX3U编程手册` 第67页），
   后者还附带一段实测报文 `01 03 00 64 00 0A`（读 D100，地址 `0x0064`=100），把"地址=寄存器号"钉死。
   → 力控 `HRS(n+1)` 换算成地址 `n` 是对的。
2. **`FX3U编程手册.pdf` 不是三菱的手册**，是《EX3U-80 系列一体机编程手册 V25.21-SL》
   （Coolmay 触摸屏 PLC 一体机）。PROTOCOL-REFERENCE 里"D128 保持区起点"的唯一出处就是它。
   **现场 PLC 是三菱原厂 FX3U 还是 Coolmay EX3U-80，目前无证据**；两者站号寄存器
   （D8414 vs D8121）与 D8400 编码（H1081 vs H0081/HE081）不同，必须先定机型（§4.6 指纹表）。
3. **`三菱FX说明书.pdf` 是 FX1S/FX1N/FX2N/FX2NC 编程手册（484 页），不是硬件手册，不涉及 MODBUS，也不覆盖 FX3U**
   （全文 `FX3U` 命中 0）。它的价值边界见 **§1.4**。**RS-485 配线/终端电阻/传输距离不在这份资料里**，
   只能靠 `FX3U编程通讯手册` 第 4 章（那部分信息很完整）。
4. **0x1F3F = 7999 的数学是对的**：`0x1F3F`=7999，`D0–D7999`=8000 点，`0x0000–0x1F3F`=0x1F40=8000 个地址 ✅。
5. **D8414 = 从站站号、范围 1–247 是对的**，但页码 p.45 错了，实际在**印刷 p.41（PAGE 46）**。
   手册还有一条被漏掉的致命注：**站号越界时从站完全不响应任何请求**。
6. **★ 32 位字序：手册规则与现场实测相反，以实测为准。**
   FX2N 编程手册印刷 p.60 明写"高位为大的号码，低位为小的号码"（即 D n=低字、D n+1=高字，
   线上应为 CDAB）；但本实验台 2026-10-03 抓包 `41 C9 99 9C` 按 **ABCD** 解出 25.2000046 ℃（合理），
   按 CDAB 解出无意义值 → **现场实际是高字在低地址**。
   **结论：保持现有 ABCD 解码，不要改成 CDAB。** 详见 §6.1。
7. **三组 D 区边界互不相同，必须分清信源**：
   FX2N（官方，印刷 p.60）= `D0–D199` 一般 / `D200–D511` 停电保持 / `D512–D7999` 停电保持专用 / `D8000–D8255` 特殊；
   Coolmay EX3U-80（兼容机，第14页）= `D0–D127` 一般 / `D128–D7999` EEPROM 保持 / `D8000–D8511` 特殊；
   官方 FX3U（MODBUS 通信篇）= 只给了 MODBUS 映射 `D0–D7999` + `D8000–D8511`，**没给保持区边界**。
8. **EEPROM 写寿命在这三份资料里查不到**（"万次""寿命""擦写"命中数全 0）。PROTOCOL-REFERENCE
   把它写成文档结论不成立；但"控制写入要少"的工程建议依然正确，见 §6.5。
9. **0x16 不是「FX3U 专有」**：它是 MODBUS 标准码（掩码写），准确说法是"FX 系列内只有 FX3U/FX3UC 实现"。
10. RTU 硬约束：**数据长度必须 8 位**，设 7 位"有可能破坏数据"（印刷 p.44）。现场 9600 8N1 合规。

|---|---|---|

| **特殊 D 区** | FX2N：**D8000–D8255（256 点）** | ❌ FX3U/EX3U-80 的 **D8000–D8511（512 点）**；且 **D8400/D8414 在 FX2N 中不存在** |
| **保持区边界** | FX2N：`D0–D199` / `D200–D511` / `D512–D7999` | ❌ 不能据此断言本机是 D128 还是 D200（FX3U 未覆盖，EX3U-80 另有规格） |

**一句话边界**：**它可以用来解释"FX 系列怎么算 32 位、D 编号怎么排、文件寄存器是什么"，
不能用来回答"这台机器 D 从哪开始保持、MODBUS 怎么收发"。**
后者分别归 EX3U-80 手册（边界）与 FX3U MODBUS 通信篇（协议）。

⚠️ **反向利用它的一个价值**：正因为 FX2N 的特殊区只到 **D8255**，
而我们的协议里要访问 **D8400 / D8414 / D8470–D8485**，
这本身就**反证了本实验台的 PLC 不可能是 FX2N 级**，而是 FX3U 级（或 FX3U 兼容机）。
这条可以用来排除"拿 FX2N 表当依据"的做法。

### 2.2 0x16 到底是不是「FX3U 专有」？

**不是。** 拆成两句话：

- 【原文】0x16 是 MODBUS 标准功能码「Mask Write Register」，FX3U 对它的动作有明确定义：
  > `FX3U编程通讯手册` PAGE 89（印刷 p.84）
  > ```
  > 仅FX3U、FX3UC可编程控制器对应。
  > 将储存在1个保持寄存器中的值通过AND或者OR进行掩码并写入值。
  > 写入保持寄存器中的掩码值如下所示。
  > 写入值＝（寄存器当前值∧AND掩码值）∨（OR掩码值∧AND掩码值）
  > ```
- 【推断】准确表述：「在 FX 系列内部，只有 FX3U/FX3UC 的 MODBUS 从站实现了 0x16」。
  PROTOCOL-REFERENCE 写「0x16 … ✓（仅 FX3U/FX3UC）」**说法本身正确**，
  但读成"FX3U 专有功能码"会误导——它是标准码，FX3U 是"支持者"不是"发明者"。

### 3.3 「D n = 地址 n」的两条独立证据

**证据 1（表格）**：§3.1 的 `0x0000～0x1F3F ↔ D0～D7999`，偏移量为 0 ⇒ D n ↔ 地址 n。

**证据 2（实测报文，最硬）**：Coolmay 手册 RD3A 例程说明"读 D100–D109"，抓包地址字段是 `00 64`：

> 【原文】`FX3U编程手册` 第79页（PAGE 80）
> ```
> 使用串口工具监控串口3 数据，得到如下结果：
> [2017:11:01:09:00:11][接收]01 03 00 64 00 0A 84 12
> [2017:11:01:09:00:11][接收]01 03 14 00 42 00 4D 00 58 00 58 00 63 00 37 00 2C 00 21 00 16 00 0B 9F C7
> ```
> 同书第72页对同一例程的说明：
> ```
> 程序表示读取从站为1 的PLC 中寄存器D100-D109 共10 个数据，保存在主站PLC 的寄存器D301-D310 中。
> ```

`0x0064 = 100` ⇒ **D100 就是地址 100**；`0x000A = 10` 个寄存器 ⇒ D100–D109。
响应 `03 14`（20 字节 = 10 个寄存器）→ `00 42`(66)、`00 4D`(77)、`00 58`(88)… 逐字对齐。

> 【工程配置·可验证】因此力控 `HRS2203`（编号 2203）↔ 地址 2202 ↔ **D2202** 的换算成立。
> 只要 HRS 遵循"编号 = 地址 + 1"，`HRS n` 就对应 `D(n-1)`。

**证据 3（逻辑反证）**：FX2N 特殊区只到 D8255（§1.2 证据 3），而协议里访问 D8400/D8414/D8470
说明本机是 FX3U 级——这同时也验证了 FX3U 表的 `0x1F40–0x213F ↔ D8000–D8511` 区间必须存在。

### 3.5 访问未定义地址的行为：异常响应，不是 0

【原文】`FX3U编程通讯手册` PAGE 123（印刷 p.118）12.6 出错码表：

> ```
> 0210  向未分配软元件的MODBUS软元件进行访问
>       所选MODBUS 软元件或者软元件＋访问点数超过从站的支持范围。
>       从站   参考上述内容
>       请确认从站的MODBUS软元件分配是否正确地设定。
>       请确认主站数据是否在所选功能的有效范围中。
>       请确认主站是否访问了有效软元件范围。
> ```

【原文】PAGE 124（印刷 p.119）「1. 对应MODBUS从站的异常响应代码」：

> ```
> 异常响应代码   异常响应代码名   详细内容
> 01H           功能代码异常     被请求的功能代码未对应从站。
> 02H           软元件异常       被请求的MODBUS软元件或访问点数超过了从站的有效范围。
> 03H           数据异常         请求文本的1个数据区域超过了有效范围。（数据长度、软元件数等）
> 04H           处理中断         从站进行请求文本的处理时，发生了致命性的出错。
> ```

**结论**：
- 访问超出映射范围（FX3U 读 0xA7C8 以上，或 Coolmay 读 0x7F00–0xA13F）→ 从站回**异常响应**，
  功能码最高位置 1（0x03→0x83、0x06→0x86、0x10→0x90），异常码 **02H**，PLC 侧存 0210。
- **不会静默返回 0**。
- 必须区分两种"访问失败"：**地址越界 → 02H 有响应**；**站号不对 → 完全无响应**（主站自己超时）。

## 6. 数据处理：32 位、保持区、文件寄存器、EEPROM、特殊区

### 6.1 ★ 32 位字序：手册规则 vs 现场实测（本文最重要的一节）

#### (a) 手册规则：高位 = 大号码

【原文·目视转录】`三菱FX说明书` **印刷 p.60（PAGE 61）** 2-9-1 数据寄存器（D）：

> ```
> 寄存器的结构与功能：
> 数据寄存器是存储数值数据的软元件，其种类如下所示。这些寄存器都是16位（最高位为正负符号），
> 将两个数据寄存器组合，可存储32位（最高位为正负符号）的数值数据。
>
> 32位：
> 以两个相邻的数据寄存器表现32位的数据。（高位为大的号码，低位为小的号码。
> 在变址寄存器中，V为高位，Z为低位。）
> 因此，可处理-2,147,483,648~2,147,483,647的数值。
>
> 在指定32位时，如果指定了低位（例如 D0），则高位为继其之后的编号（例如 D1）被自动占有。
> 低位可用奇数或偶数的任一种软元件编号指定。
> 考虑到外围设备的监视功能，建议低位采用偶数软元件编号。
> ```

⇒ **规则：`D n` = 低 16 位，`D n+1` = 高 16 位。**

#### (b) 由规则推出的线上字节序 = CDAB

MODBUS 侧 `D n ↔ 地址 n`（§3.3）：一个 float 若按上述规则存在 `D125/D126`，
则 `D125`=低字、`D126`=高字，线上应发出 `[低字][高字]`。对 25.2000046 ℃（IEEE754 = `41 C9 99 9C`，
其中 `41C9` 是高字、`999C` 是低字）：

| 顺序 | 寄存器1 | 寄存器2 | 线上字节 | 解码结果 |
|---|---|---|---|---|
| 按 FX 规则（低字先） | D125=0x999C | D126=0x41C9 | `99 9C 41 C9` | 需按 **CDAB** 交换字才能还原 25.2 |
| **现场实测** | **D125=0x41C9** | **D126=0x999C** | **`41 C9 99 9C`** | 直接按 **ABCD** 还原 |

#### (c) 现场实测：高字在低地址

> 【工程实测】本实验台 **2026-10-03 真实抓包**：读 **D125 起 2 个寄存器**，返回
> **`41 C9 99 9C`**，按 **ABCD**（大端、不交换）解码 = **25.2000046 ℃**（合理温度）；
> 若按 CDAB 交换字解码得 `0x999C41C9` ≈ **-1.19e-23**，是无意义值。
> ⇒ **现场实际是"高字在低地址"**，与 FX 手册的通用规则**相反**。

#### (d) MODBUS 通信篇里有没有字序说明？——没有

【未覆盖】实测关键词命中（`FX3U编程通讯手册.txt` 全文）：

| 关键词 | 命中 | 结论 |
|---|---|---|
| `字序` | **0** | 无 |
| `高低` | **0** | 无 |
| `字节序` | **0** | 无 |
| `交换` | **0** | 无 |
| `32位数据` | **0** | 无 |
| `双字` | 1 | 仅 9.4.1 的"32位计数器CN200～255：1双字" |
| `高位` / `低位` | 18 / 16 | 全是「最高位/最低位（bit）」「高位字节/低位字节」语境 |

**唯一相关的一条只管"一个字内部的字节序"，不管"两个字之间"**：

> 【原文】`FX3U编程通讯手册` PAGE 61（印刷 p.56）7.3 各功能的协议数据部格式（数据格式图注）
> ```
> 2个字节作为1个数据时，以高位字节（8位）为（H），以低位字节（8位）为（L）。
> 注:没有高位字节与低位字节的更换。
> ```

⇒ 含义：**16 位寄存器内部 = 高字节在前、且明确禁止字节交换**。
这一条正好支持我们 `41 C9` / `99 9C` 的字节排列方式（每个字内部不换字节），
把"要不要字节交换"这个问题**排除了**；剩下的只有"字与字之间谁在前"。

#### (e) 结论与工程决定

| 项 | 结论 |
|---|---|
| 手册规则 | `D n`=低字、`D n+1`=高字 ⇒ 线上 CDAB |
| **现场实测** | **高字在低地址 ⇒ 线上 ABCD** |
| **以谁为准** | **以现场实测为准**（手册规则只适用于"PLC 按 32 位指令直接存储"的理想情况，本机显然不是） |
| **代码决策** | ✅ **保持现有 ABCD 解码，不要改成 CDAB** |
| 字节交换 | ❌ 不需要（p.56 明确"没有高位字节与低位字节的更换"） |
| 例外 | ⚠ **每个 32 位量要独立判定**：`DDSU666` 的 float 字节序是**电表规格**，不能套 PLC 规则 |

> 【推断】现场出现"高字在前"的可能原因（需现场确认，见 §9.7 V5）：
> (a) PLC 程序用 `SWAP`/字交换指令或两条 16 位指令分别写入；
> (b) 该值由触摸屏/上位机以 32 位方式写入，写入口径与 PLC 32 位指令不同；
> (c) 值来自模拟量模块 BFM 的 32 位读取后再手工拆分。
> **不论原因，实测优先**；但要在代码注释里写明"本机字序为高字在前（实测）"，
> 避免后来者按手册"修正"成 CDAB 反而改坏。

### 6.2 掉电保持区：三组边界互不相同

这是最容易出错的一条。**三份资料给出的是三台不同机器的规格**，必须分清。

#### (a) 官方 FX2N（`三菱FX说明书` 印刷 p.60）

#### (c) 官方 FX3U（`FX3U编程通讯手册`）—— **只给映射，不给边界**

【未覆盖】`FX3U编程通讯手册` 全文 `停电保持` 命中 **0**、`电池` 命中 **0**、`EEPROM` 命中 **0**。

- **PROTOCOL-REFERENCE 写「D0–D127 / D128–D7999 / D8000–D8511」并标"FX3U编程手册 p.14"
  ——引用指向的是 Coolmay EX3U-80，不是三菱 FX3U。** 这个值**只对兼容机成立**。
- **若现场是三菱原厂 FX3U**：按 FX2N 官方规则（D200 起保持）**推断**为

  但**官方 FX3U 的边界在这三份资料里仍然查不到**，这个"D200"属于

- **对本项目实际无影响**：我们要写的 `D2000`（风机）、`D2001/D2201`（模式）、`D2202`（温度设定）、

  所以"写进去断电还在"这个观察**不能用来区分机型**；要区分必须测 D128–D199（§9.7 V4）。

### 6.3 文件寄存器：D1000 以后可能被改成文件寄存器（★ 与我们直接相关）

【原文·目视转录】`三菱FX说明书` **印刷 p.64（PAGE 65）**「2-9-3. FX1N, FX2N, FX2NC 可编程控制器的文件寄存器 [D]」

> ```
> ● 数据寄存器D1000以后是普通用的保持用寄存器，可通过参数设定作为最大7000点的文件寄存器使用。
> ● 通过参数设定，可指定1~14个块（1个块相当于500个文件寄存器）。
>   但是1个记录块相当于减少了500步的程序储存区域。
> ● 将D1000以后的一部分设定为文件寄存器时，剩余部分可作为通用的保持寄存器使用。
>
> ● 当可编程控制器从STOP→RUN时，在内置内存可选内存中设定的文件寄存器区域【A】，
>   被批量传送至系统RAM中的数据储存区域【B】部。随后，在程序中使用的软元件编号以及
>   除FNC15(BMOV)之外的应用指令中的操作数的指定全部是针对数据寄存器区域【B】工作的。
>
> ● 在外部设备上对文件寄存器进行监视时，将数据寄存器内的数据寄存器区域【B】读出。
>   而且从外部设备进行文件寄存器软元件的"当前值变更"、"强制复位"或"PC内存的全部清除"的情况下，
>   是对程序储存区内的文件寄存器区域【A】部进行修改，随后向数据寄存器区域【B】部自动传送。
>
> ● 因此，对文件寄存器软元件进行改写时的程序存储器需要将内置内存/可选RAM内存或
>   [EEPROM内存]的保护开关为OFF状态。（在EPROM内存或EEPROM内存的保护开关为ON状态时，
>   不可以从外部设备进行修改。）
> ```

**为什么和我们直接相关**：

【工程配置】我们的写入目标 **D2000 / D2001 / D2201 / D2202 / D2207 全部 ≥ D1000**。
如果现场 PLC 的参数里把 D1000 以后配置成了文件寄存器（最多 7000 点 = D1000–D7999），那么：

1. 这些点是**文件寄存器**而不是普通保持寄存器，`STOP→RUN` 时会被区域【A】批量覆盖 ——
   **我们写进区域【B】的值在下次 STOP→RUN 后可能被【A】的值冲掉**；
2. 外部设备（我们）改写文件寄存器时，实际写的是【A】再自动传【B】，
   这一步还受 **EEPROM/EPROM 保护开关**影响（开关 ON 时**外部设备不能修改**）；
3. 也就是说，**"写成功了但下次上电变回原值"/ "写返回异常"都可能源于文件寄存器配置**。

> 【推断】本实验台的 D2000 写入能保持（现场已观察到写入 3、8 一直保留），
> 说明当前 **D1000 以后大概率没有被配置成文件寄存器**，或写入路径正常。
> 但这是**行为反推**，必须在参数里确认（§9.7 V12）。
> 注意：FX3U 的文件寄存器机制比 FX2N 更强（可用 `FNC15 BMOV` 与 `R` 寄存器做真正断电保持），
> 若现场用 `R` 寄存器做保存，则 `D` 区可能只是易失暂存——这一点更需要 PLC 程序才能确认。

## 7. 通信时序与异常

### 7.1 3.5 字符帧间隔与请求间延迟

【原文】`FX3U编程通讯手册` PAGE 57（印刷 p.52）7.2.1 RTU 帧：

> ```
> Start   地址字段 1个字节   功能代码 1个字节   数据 0～252个字节   出错检查（CRC）2个字节   END
> 3.5个字符时间 以上的间隔                                     3.5个字符时间 以上的间隔
> 出错检查计算范围
> ```

【原文】PAGE 46（印刷 p.41）D8411「请求间延迟（帧间延迟）」：

> ```
> 该延迟是从发送请求文本后到发送下一个请求文本的等待时间。通过这段时间可检测出文本结束。
> 设定范围:0～16382［ms］
> 设定0时，为3.5个字符时间。
> 设定3.5个字符时间以下的值时，主站在3.5个字符时间的等待时间中，会发送下一个请求。
> ```

字符长度公式（【原文】PAGE 22，印刷 p.17）：

> ```
> 字符长度（位）: 开始位（1bit）＋数据长度（7bit/8bit）＋奇偶性（0bit/1bit）＋停止位（1bit/2bit）
> 3.5个字符×字符长度（位）
> T10＝ ──────────────────── ×1000（ms）＋1ms
>              波特率（bps）
> ```

**9600 8N1 实算**：字符长度 = 1 + 8 + 0 + 1 = **10 bit**；1 字符 = 10/9600 = **1.0417 ms**；
**3.5 字符 = 3.65 ms**（手册公式再加 1 ms → 4.65 ms）。

另有一条给主站侧的补充要求（正适用于我们的上位机）：

> 【原文】PAGE 115（印刷 p.110）10.4-5「FX可编程控制器为从站时」
> ```
> FX可编程控制器为从站的情况下，从对象设备侧向可编程控制器侧发送指令时，
> 请在可编程控制器响应超过100μs后，再发送下一个指令。
> ```

⇒ **下一帧最早只能在"收到响应 + 100 μs"之后发**，实际要留 3.5 字符（3.65 ms）才稳。

【原文】PAGE 57（印刷 p.52）

> 【原文】PAGE 45（印刷 p.40）D8410：
> ```

> 0的情况下，为400ms的延迟。
> 注2: 设定3.5 个字符时间（文本间隔）以下的值时，主站在3.5 个字符时间的等待时间中，会发送下一个请求。
> 注3: 播放延迟和请求间延迟请配合网络上最慢的从站。

**直接给上位机用的一条**：

> 【原文】PAGE 114（印刷 p.109）10.4-4「FX系列可编程控制器为从站时」
> ```
> 请将主站侧的播放延迟设定成与FX系列从站的扫描时间相同或比该扫描时间长。
> ```

### 7.4 从站响应时间：由 PLC 扫描周期决定

【原文】PAGE 22（印刷 p.17）2.2 链接时间，从站侧处理时间：

> ```
> 请求文本处理时间（Ts）通过下列计算式以ms单位计算。
> Ts＝T11＋T12＋T13
> T11＝T14＋T15＋最大扫描时间
> T15＝D8411或D8431（依据通信通道）
> T12＝不足1ms
> ```

⇒ **从站"收到完整请求 → 开始回"的间隔 ≈ 最大扫描时间 + 帧间延迟**。
所以**超时必须大于 PLC 最大扫描周期**；`D8012`（扫描时间最大值，地址 8012）就是用来定它的。
RTU 下 `T10 = 0`（【原文】PAGE 22 `RTU模式: T10＝0`），不需要 ASCII 的结束码等待。

**处置优先级**（【推断】从文档条件反推）：

1. 完全无响应 → 先查**站号 D8414**（越界静默，§4.3）→ 接线 A/B 是否反、终端电阻 → 波特率。
2. 偶发 CRC 错（0205）→ 终端电阻/屏蔽接地/线长/与动力线并行。
3. 偶发帧错或字符溢出（0204/0206）→ **主站并发**或两帧间隔 <3.5 字符。
4. 有响应但异常码 02H → 地址越界或自定义映射（§3.4/§3.5）。
5. 异常码 03H → 一次读的点数 >125 或 >123。

| 5-3 | 字节交换注意事项 | **✓ 已可排除** | 【原文】`FX3U编程通讯手册` 印刷 p.56：`2个字节作为1个数据时，以高位字节（8位）为（H）…注:没有高位字节与低位字节的更换。` ⇒ **字内部不换字节** |
| 5-4 | "读取时一次读 2 个寄存器" | **✓ 正确** | 与 125 点上限不冲突 |
| 5-5 | 未说明"每个 32 位量要独立判定字序" | **△ 补充** | 电表 float 是**电表规格**，不能套 PLC 规则（§6.1e） |

> **9600 8N1 完全满足 FX3U 的 RTU 从站要求**，不需要改。

### 9.2 帧格式与缓冲（必须）

| 项 | 要求 | 依据 |
|---|---|---|
| 帧结构 | `[≥3.5字符] 地址 1B + FC 1B + 数据 0–252B + CRC 2B [≥3.5字符]` | p.52 |
| CRC | CRC-16/MODBUS（多项式 0xA001，初值 0xFFFF），**低字节先发** | p.52 |
| 最大帧 | **256 字节** | p.52；p.117 0206 阈值 |
| 读缓冲 | ≥ **300 字节** | 【推断】 |
| 广播 | 地址 0 = 广播（只写无响应）。本项目**不要用广播** | p.51 |
| 半双工 | 同一时刻**只允许一帧在线上**；从站"可同时受理的请求文本数 = 1" | p.15 |

> ⚠️ **实现要求**：`Protocol.cs` 必须有全局串行锁，禁止并发请求。
> 并发会触发 0206「前一个请求的处理过程中，接收到其他请求（仅从站）」。

### 9.3 超时、重试、帧间隔建议

**先算清客观需要的时间**（9600 / 10 bit/字符）：

| 场景 | 报文长度 | 线上时间 |
|---|---|---|
| 3.5 字符间隔 | 3.5 字符 | **3.65 ms** |
| 0x03 读 1 个寄存器 | 请求 8B / 响应 7B | 8.3 / 7.3 ms |
| 0x03 读 8 个寄存器 | 请求 8B / 响应 21B | 8.3 / **21.9 ms** |
| 0x03 读 125 个寄存器（上限） | 请求 8B / 响应 255B | 8.3 / **265.6 ms** |
| 0x10 写 123 个寄存器（上限） | 请求 255B / 响应 8B | **265.6** / 8.3 ms |
| 最大帧 256B | — | **266.7 ms** |

| 参数 | 建议值 | 理由 |
|---|---|---|
| 单帧读超时 | **500 ms** | 覆盖"扫描周期 + 125 点响应 266 ms"；只读 ≤10 点可降至 300 ms |
| 写后回读超时 | 500 ms | 需等 PLC 扫描一轮才生效（`T11 = T14+T15+最大扫描时间`，p.17） |
| 重试次数 | **2** | 对齐 D8412 语义（0–20）；连续失败多为接线/站号问题 |
| 帧间隔（请求→下一请求） | **≥ 5 ms**（保守 10 ms） | 3.5 字符 = 3.65 ms（p.52）；手册实例用 K10（p.36） |
| 收到响应→下一请求 | **≥ 3.65 ms**，硬性 ≥ **100 μs** | p.110 `请在可编程控制器响应超过100μs后，再发送下一个指令` |
| 轮询周期 | ≥ 1 s（建议 1–2 s） | 监测量无需更快；也降总线/EEPROM 压力 |
| 扫描周期参考 | 读 **D8012**（地址 8012） | p.109 `请将主站侧的播放延迟设定成与FX系列从站的扫描时间相同或比该扫描时间长` |

> 【必须】超时值 **不能小于 PLC 最大扫描周期**，否则把"PLC 还在扫"当"没响应"，
> 造成假超时 + 重试风暴（重试叠加进一步触发 0206）。

### 9.4 写保护建议（本项目最需落地的一条）

**为什么必须做**：

1. 保持区是 **EEPROM**（Coolmay 第14页 `EEPROM 保持用(16 位) D128～D7999`），写入是物理擦写；
2. **寿命次数任何文档都查不到**（§6.4）→ 只能按最坏情况设计；
3. 写入目标 **D2000 / D2001(或 D2201) / D2202 / D2207 全部落在保持区**，
   且**全部 ≥ D1000**，可能还受**文件寄存器**机制影响（§6.3）；
4. 从站是**单请求串行**设备（p.15），写操作占用整条总线。

| # | 规则 | 说明 |
|---|---|---|
| W1 | **只在用户显式点"下发/确认"时写**，禁止定时/周期/自动补偿写 | `control-config.json` 的 4 个控制点全部走"人工单次" |
| W2 | **写值不变则不写**（写前先读，值相同跳过） | 消除 UI 抖动导致的重复写 |
| W3 | **同一寄存器 1 分钟内最多写 1 次**（软件节流） | 【推断】把年写入量压到 <1 万次量级 |
| W4 | **写完立即回读校验**（0x06 回显 + 0x03 回读双确认） | 0x06 成功判据 = 从站原样回显（p.63）；回读失败要告警而非静默 |
| W5 | **绝不写 D8000–D8511** | 含 D8414 站号、D8400 通信参数、D8120；误写会让从站失联（§6.5、§4.3） |
| W6 | **不要拿 D128–D199 做写入测试**（除非现场工程师在场） | 若现场是原厂 FX3U，这段可能是一般用区（非保持），且可能被 PLC 程序用作暂存 |
| W7 | **批量写用 0x10 而不是 N 次 0x06**（连续寄存器时） | 1 次 EEPROM 事务 vs N 次；上限 123 点 |
| W8 | **写失败（02H/03H）不重试同一帧** | 02H=地址越界，重试必然再错 |
| W9 | **首次上线前读 D8470–D8485 确认映射未被自定义** | 否则所有地址错位（§3.4） |
| W10 | **确认 D1000 以后是否被配成文件寄存器** | 若是，写入可能在下一次 STOP→RUN 被区域【A】覆盖（§6.3） |

> 【工程配置·风险提示】若 `CONTROL-DESIGN.md` 存在"设定值随动/自动同步"逻辑，
> 需复核是否会在 UI 刷新时回写同一值——这是 EEPROM 寿命的头号杀手。

### 9.5 采集分块、地址换算与 32 位解码

| 项 | 要求 | 依据 |
|---|---|---|
| 单次读上限 | **125 寄存器** | p.48/p.60 |
| 单次写上限 | **123 寄存器**（0x10）/ 1（0x06） | p.49 |
| 现状 | 现场 PLC 点表 ≤11 点，**无需分块** | 【工程配置】 |
| 地址换算 | `地址 = D编号`（D2000 → 2000 = 0x07D0） | p.97 + 第79页报文 |
| 非法地址 | 收到 `0x83 + 02` → 判"地址越界"，记日志并停用该点 | p.119 |
| **32 位解码** | **保持 ABCD（大端、字不交换、字节不交换）** | 【工程实测】2026-10-03 抓包 `41 C9 99 9C` → 25.2000046 ℃（§6.1） |
| **禁止** | ❌ 不要"按手册改成 CDAB" | 手册规则（印刷 p.60）与本机实测相反，改则必错 |

> 【工程配置·注释要求】在解码处写明：
> `// 本机实测字序为「高字在低地址」(2026-10-03 抓包 41 C9 99 9C = 25.2℃)，
> // 与 FX2N 编程手册 p.60 通用规则相反，勿改为 CDAB。`
> 防止后来者"照手册修正"反而改坏。

### 9.6 异常处理与诊断（建议落到 `Protocol.cs`）

| 现象 | 判定 | 处置 |
|---|---|---|
| 无响应（超时） | 站号错 / 接线反 / 波特率错 / PLC 断电 | 重试 2 次 → 报"通信中断"；提示检查 D8414 与接线 |
| 响应帧 CRC 错 | 噪声 / 终端电阻缺失 / 帧间隔不足 | 丢弃重试；连续 3 次告警 |
| 异常帧 `83 02` | 地址越界或点数超限 | 永不再试，标记该点配置错误 |
| 异常帧 `86 03` | 写数据/地址非法 | 检查写入值范围 |
| 异常帧 `83 01` | 功能码不支持（如误发 0x16 给 FX3S） | 检查机型 |
| 帧长度 < 5 字节 | 半帧/噪声 | 丢弃重试（p.117 0205 亦以 ≤3 字为 CRC 错） |
| 读到全 0 且持续 | 可能真为 0，也可能地址错位（自定义映射） | 交叉验证：读 D8470–D8485 是否全 0 |
| 写入成功但上电变回原值 | 文件寄存器区域【A】覆盖，或保护开关 ON | 查参数（§6.3、§9.7 V12） |

**建议新增的"体检"读数（只读，人工触发）**：
`D8001`（8001）、`D8010–D8012`（8010–8012）、`D8400`（8400）、`D8401`（8401）、
`D8414`（8414）、`D8120`/`D8121`（若 Coolmay 串口2）、`D8470–D8485`（8470–8485）。

### 9.7 ★ 仍需现场确认的事项（含验证方法）

|---|---|---|---|
