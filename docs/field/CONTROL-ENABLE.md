# 控制写入启用规程

> **出厂状态：4 个控制点全部不可写。**
> 这是有意的：0.7.1 及更早版本里，"未确认"和"未开放"两道闸门**实际上从未生效**，
> 审计日志里有 10 笔写进真实 PLC 的记录发生在"配置声明不可写"的情况下。

## 1. 为什么默认关闭

`control-config.json` 里每个控制点有两个字段：

| 字段 | 含义 |
|---|---|
| `confirmed` | 这个点的**语义**是否已现场确认（它到底是控制什么） |
| `allowWrite` | 是否允许真实写入 |

两个字段**各自独立生效**。任一为 `false`，该点就写不进去，一条 06 报文都不会发出。

## 2. 当前 4 个控制点的状态与未决项

| 点 | 名称 | 已观察到的值 | 未决事项 |
|---|---|---|---|
| `D2202` | 主机温度设定 | 0 / 1 / 3 / 8 | 量程按 ℃ 推断（实测只出现过 0–8），单位待确认 |
| `D2001` | 模式控制 | **恒 0** | **地址本身待裁决**：点名写 2001，力控连接项是 2201 |
| `D2000` | 送风风机速度 | 0 / 1 / 2 / 50 | 写 50 时风机档位 D2209 不动 ⇒ 联动已被证伪 |
| `D2207` | 放冷反馈设定 | **恒 0** | 语义未确认 |

**这四个点目前一个都不建议开启。**

## 3. 开启某一个点的完整步骤

### 第 1 步：确认语义（必须有现场证据）

不是"看起来像"，是要有一条能复现的证据链，例如：

- 在设备面板上把某个开关从 A 打到 B
- 同时在本程序的「通信诊断」页对该寄存器单点读
- 看到读数跟着变，且**重复 3 次都一致**

把结论写进该点的 `note` 字段（写清楚日期、操作、观察到的变化）。

### 第 2 步：改配置

编辑 `control-config.json`，找到该点，把两个字段改成 `true`：

```json
{
  "point": "D2202",
  "label": "主机温度设定",
  ...
  "confirmed": true,
  "allowWrite": true,
  ...
}
```

**只改这两个字段，不要动 `min`/`max`。** 量程是第二道防线，改坏了会挡住后续合法写入。

### 第 3 步：配置因果判据（强烈建议）

同一个点还有 `feedbackPoints` 字段，用来回答"写进去之后，怎么知道设备真的动了"：

```json
"feedbackPoints": ["T1"]
```

- 为空 ⇒ 程序**不会**说"设备已动作"，只会说"无法判定（未配置因果判据）"
- 填了 ⇒ 程序会在写入后观察这些点，并报告"设备已动作"或"未动作"

**只填有因果关系的点。** 会自己跳变的点不能填（例如 D2212 是 PLC 定时斜坡，
D2209 与 D2000 的联动已被证伪）。

### 第 4 步：重启并验证

1. 重新启动程序（配置只在连接时重载）。
2. 「运行控制」页，该点应显示可发送。
3. **第一次写入用一个明显安全的中间值**，不要用边界值。
4. 观察四段胶囊：`①下发 ②回显 ③回读 ④设备`。

## 4. 写入结果怎么读

| 状态 | 含义 | 该怎么办 |
|---|---|---|
| `held` | 寄存器回读已是新值 | 等下一轮采集观测，会自动升为 `applied` 或 `reverted` |
| `applied` | 下一轮采集观测也一致 | 成功 |
| `reverted` | 下一轮采集又变回去了 | 设备不认这个值，检查量程/模式 |
| `not_accepted` | 回读仍是旧值 | PLC 没接受，通常是被其它逻辑覆盖 |
| `mismatch` | 回读既不是旧值也不是新值 | 有第三方在改这个寄存器 |
| `pre_read_failed` | 写前 03 预读失败 | **本次未发送任何报文**，检查连接 |
| `unknown` | 结果未知，控制被锁定 | 点「重新读取核对」 |
| `verify_reason_required` | 核对读到第三值，缺理由码 | 必须填理由码才能解锁 |

## 5. 审计

每次操作写两处：

- `logs\control-events.jsonl`（每行一个 JSON）
- 数据库 `control_events` 表

关键字段：
- `write_id`：一笔写入的唯一标识，贯穿界面终态与审计行
- `evidence`：`tx|rx|pre|rb|effect|gate|note|ms|epoch` 串在一起的证据
- `old_value` / `readback`：**可以为空**（旧版本会把"从未发生的旧值"记成 0）

## 6. 绝对不要做的事

- **不要**为了"让它能写"而把 `mode` 改成旧写法以外的值来绕过 —— `mode` 只控制总开关。
- **不要**一次把 4 个点全部开启。一次开一个，验证通过再开下一个。
- **不要**在没配 `feedbackPoints` 的情况下把"写入成功"当成"设备动了"。
- **不要**用边界值（`min` 或 `max`）做第一次写入。
