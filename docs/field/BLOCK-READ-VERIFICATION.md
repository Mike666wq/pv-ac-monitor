# 块读试读清单（启用前必须逐项通过）

> 块读功能**代码已就绪但默认未启用**。启用前必须在本机完成下面的逐块试读。
> 全部通过后，把 `protocol.json` 的 `block_read_enabled` 改为 `true` 即可（见文末）。
>
> 工具：「通信诊断」页，站号 / 地址 / 数量 / 模式四个输入框，逐块发一次读。
> **全程只发功能码 03（读），不写任何寄存器。**

## 每块的判定标准

对每一块，记录这四项：

1. **RX 长度** = `5 + 2 × 数量` 字节
2. **功能码** = `0x03`（不是 `0x83`）
3. **耗时** ≤ 50 ms + PLC 扫描时间（几百毫秒以内）
4. **数值合理**：与逐点读的结果一致（偏差在执行器动作范围内可接受）

任一项不通过 ⇒ **该块退回逐点读**，不要强行启用。

## 关键判据：块读 vs 逐点读对拍

选 3 个**慢变量**（不会自己快速跳变的点），交替"块读 / 逐点读"各 5 轮：

- 推荐：`D8`（累计电能）、`T0`（相变1）、`DU8`（市电累计电能）
- **不要选** `D2`/`D3`/`D5`/`D4`（电流/功率在压缩机启停瞬间会剧烈变化，
  两次读必然不同，比不出结果）

**判定**：5 轮里至少 4 轮逐位相同 ⇒ 通过。

## 启用方法（全部试读通过后）

`protocol.json` 顶层加一行：

```json
"block_read_enabled": true
```

保存后重启程序。日志里会出现 `BLOCK slave=2 [125,12] ...` 这样的行，
并且每轮的 `SAMPLE` 行数与之前相同（**仍然是 37 行**）。

## 回退方法

把 `block_read_enabled` 改回 `false`（或删掉这一行），重启。30 秒内回到逐点读。

## 为什么值得做（不只是"更快"）

现在 37 个点分成 37 帧，一轮大约 1.1 秒。同一轮的 `D3`（有功）、`D4`（无功）、
`D5`（视在）**最多相差 1.1 秒** —— 而"P²+Q²≈S²"这个判据要求三者是同一瞬间的值。
现状下这个恒等式在数学上就不成立（仿真器自测就差 11%）。

块读后 `[8192,12]` 一次拿到 `D1`~`D6` ⇒ **P/Q/S 严格同一帧、同一采样瞬间**。
这是"更对"，不只是"更快"。
