# 故障排查手册

按"你看到的现象"查表。左边是现象，中间是最可能的原因（按概率排序），
右边是处置。**处置完一轮仍不对，就停在这里不要反复试** —— 反复试会掩盖线索。

## 1. 双击程序没反应 / 一闪而过

| 原因 | 处置 |
|---|---|
| .NET Framework 4.8 缺失 | 装 .NET Framework 4.8 运行时 |
| 目录不可写，`settings.json` 写失败 | 换到用户可写目录（见 INSTALL.md 第 1 节） |
| 被杀毒软件拦截 | 加白名单；程序未签名，部分杀软会误报 |

## 2. 点「连接」后显示已连接，但所有卡片都是 `—`

| 原因 | 处置 |
|---|---|
| 端口选错（最常见） | 设备管理器确认 RS485 转换器的实际 COM 号，重选 |
| A/B 线接反 | 断电后对调 RS485 的 A、B 两根线 |
| 设备未上电 | 查设备电源指示灯 |
| 从站号不符 | 通信诊断页按站号 1/2/3/6 逐点试读 |

## 3. 状态栏显示 `2/4 设备` 或 `3/4 设备`

**分母才是关键**：有设备没响应，但链路是通的。

看总览页哪个分区整片 `○ 未接入`：
- 「市电 · 7」全空 → DDSU666（站号 6）问题，见第 7 条
- 「太阳能 · 3」全空 → DJSF6682（站号 1）问题，见第 8 条
- 「温度」全空 → PLC（站号 2）问题，见第 2 条

## 4. 卡片显示 `超时 · 陈旧 12s` 并一直不恢复

该点持续读不到。看「通信诊断」页对同一地址单独发一次读：
- 单点能读、连续采集读不到 → 该站被其它设备拖慢，把采集周期调大（如 10 s）
- 单点也读不到 → 设备侧问题

## 5. 卡片上的数字突然变成 `—`

程序在**超过 60 秒**没有新数据时清空数值。这是有意的：一个 10 分钟前的
数字看起来和现在的数字一模一样，最容易让人误判。

处置：查为什么 60 秒没数据（链路、设备、采集是否被停）。

## 6. 卡片带 `△` 标记

该点**语义未现场裁决**或**单位带限定语**（如"二次侧"）。

值可以看、可以做趋势，但**不要用它做结论**（不要写进报告的温度/效率结论）。
当前带 `△` 的点：T1、D2206、D2209~D2213、D2000~D2207、D9、ZI6682、ZW66822、0006H。

## 7. 「市电 · 7」整片无数据（DDSU666 站号 6）

**已知问题**：该表最后一次成功通信是 2026-09-30，之后恒无响应。

排查顺序：
1. 表是否上电（面板有无显示）
2. 从站号是否为 6（通信诊断页按 1~8 逐号试读）
3. RS485 A/B 是否接反
4. 表内通信参数（地址码/波特率）是否被改过

**这是设备/接线问题，程序无法通过软件恢复。**

## 8. 「太阳能 · 3」有电压但电流/功率是 0

DJSF6682 的电流、功率是**二次侧数据**，需要乘分流器倍数才是实际值，
**倍数尚未确认**。夜间/停机时本来就是 0。
要得到绝对值，需要：发电状态下的采样 + 独立基准（充电器面板电流、组件铭牌 Voc/Isc 或钳形表）。

## 9. 记录条数不增长 / 底部显示「! 记录 · 失败」

| 原因 | 处置 |
|---|---|
| 磁盘可用空间低于 100 MB | 清理磁盘；程序会主动停止记录以免写坏库 |
| 数据目录不可写 | 见 INSTALL.md 第 1 节 |
| 数据库被外部程序独占 | 关闭正在读取该 .db 的 SQLite 工具 |

## 10. 导出时提示"当前进程无法写入所选导出目录"

所选导出目录不可写。换到用户目录下（如 `文档\实验导出\`）。

## 11. 导出后 Excel 里名称和界面上不一样

**这是正确的。** 导出保留**采集当时**的名称与单位，不是今天的名称。
明细表有「元数据来源」列标明是「行内」还是「当前点表」。

例：2026-11-03 采集的 T1 在导出里叫「水箱」（当时的名字），
今天界面上叫「主机罐温度」。历史记录不该被今天的改动改写。

## 12. 想确认某个点到底是哪个寄存器

总览页每张卡片悬停有提示：`设备 · 站号 · 地址 · 名称`。
或者在标题栏「查找」里输点名/名称/地址，会定位到该卡片。

寄存器地址 = 点名里的数字（`D2202` ↔ 地址 2202），`0006H` 是十六进制直写。

## 附：日志在哪

| 文件 | 内容 |
|---|---|
| `logs\session-*.log` | 每轮的逐点结果、SKIP 原因、站号恢复 |
| `logs\control-events.jsonl` | 每次控制操作的审计（含 write_id、理由码） |
| `logs\diagnostics.jsonl` | 通信诊断页每次收发 |
| `point-catalog-validation.json` | 启动时的点表校验结果 |

**排查任何问题先看 `logs\session-*.log`**，里面有每一笔事务的 TX/RX 和耗时。
