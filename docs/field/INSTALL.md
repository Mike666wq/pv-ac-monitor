# 安装与首跑（现场必读）

## 1. 目录必须在"当前用户可写"的位置

程序把 `settings.json`、`data\`、`logs\` 写在自己所在目录。

**不要把程序解压到以下位置**（会静默写不进去，表现是"能连上但什么都没记录"）：

- `C:\Program Files\`、`C:\Program Files (x86)\`
- 任何 UNC 网络路径（`\\server\share\...`）
- 只读介质（光盘、只读 U 盘分区）

**推荐**：`D:\BMS\PV-AC-Monitor\` 或 `C:\Users\<你的账号>\Desktop\PV-AC-Monitor\`。

判断方法：在这个目录里新建一个记事本文件，能保存成功就是可写的。

## 2. 运行环境

- Windows 7 SP1 及以上（实测 Windows 10/11）
- **.NET Framework 4.8**（多数 Win10 1809+ 已自带；缺失时程序会提示，不会静默退出）
- USB-RS485 转换器 + 对应驱动（设备管理器里应出现 COM 口）

## 3. 首跑步骤

1. 解压发布包到可写目录。
2. 双击 `ExperimentMonitorDemo.exe`。
3. 左侧勾选框**不勾**「模拟数据」。
4. 「串口」下拉里选接 RS485 的那个口。
5. 点右上角「连接」。

**判断连接是否真的成功，看两处：**

- 底部状态栏第一段：`● 链路 · 已连接 · COMx · 3/4 设备`
- **重点是那个分母**。串口打开 ≠ 设备都在。显示 `0/4 设备` 说明口开对了但
  A/B 接反、从站号不对或设备没上电。

## 4. 端口默认值的陷阱

程序记住「上次成功用过的端口」，而不是「上次在下拉框里选过的值」。
但**第一次运行时它可能默认选中编号最小的口**（例如 COM3），
那个口往往不是你的 RS485 转换器 —— 表现出来就是"连接成功、数据全无"。

第一次请手动确认端口号。设备管理器 →「端口 (COM 和 LPT)」可以查到。

## 5. 与力控并存

程序**不写 PLC 任何寄存器**（控制功能出厂全部关闭，见 `CONTROL-ENABLE.md`），
也不会修改力控的任何文件。两者可以同时运行。

但**同一条 RS485 总线上不能有两个 MODBUS 主站**。二选一：

- 方案 A（推荐先做）：停力控采集，用本程序采集，确认数据正常。
- 方案 B：保留力控，本程序只做只读诊断（通信诊断页逐点读，不启动连续采集）。

切换回力控：本程序点「停止」→「断开连接」→ 关程序 → 启动力控采集。

## 6. 第一件事：核对三个数字

启动后、开始采集前，先确认这三件事，否则后面所有数据都不可信：

| 位置 | 应该看到 | 如果不对 |
|---|---|---|
| 底部状态栏 | `● 链路 · 已连接 · COMx · 4/4 设备` | 4 台设备里哪台没数，看总览页哪个分区全是 `○ 未接入` |
| 总览页「温度 · 7」 | 7 张卡片都有读数，不是 `—` | 有 `—` 说明该点没读到 |
| 总览页「指令 / 设定」 | 显示「设定 X · 实测 Y · 已跟踪/未被跟踪」 | 只有裸数字说明点表未配对（联系开发） |

## 7. 已知的现场状态（2026-11 交接时）

- **市电表 DDSU666（站号 6）自 2026-09-30 起无响应**，市电分区会显示
  `○ 未接入`。这是设备/接线问题，不是程序问题。程序会对它做隔离重试
  （5/10/20/40/60/120/300 秒），不影响其它三台设备采集。
- 直流表 DJSF6682（站号 1）的电流/功率标着 `△ 存疑`：分流器倍数未确认，
  数值只能看趋势，不能当绝对值用。
